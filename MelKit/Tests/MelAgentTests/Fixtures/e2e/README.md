Scripted (not recorded) runs for core's end-to-end tests in `MelTests/Session/EndToEndTests.swift`. Each file is one Mel run in the record shapes of the 2.1.311 recordings next door: `system/init`, `stream_event` text deltas, `assistant` `tool_use`, `result`. `fake-claude.sh` replays them through the real `AgentRunner` and `ClaudeCode.parse`.

`v2/` holds one script per spec size, named by prefix, in the order the tests run them:

- `qf-*`: Quick fix. `intake` (JSON in `result`), `spec`.
- `ft-*`: Feature. `intake`, `requirements` (reads the attachment), `architecture`, `tasks`, `analyze` (`{"issues": []}` in a fence; analyze replies hold contradictions only, coverage is Mel's own check). The project-context run before it is the real recording `claude-2.1.311-project-context.jsonl`.
- `pr-*`: Product, on the board. `intake` (names the spec), `product`, `requirements-asked` (the whole file, ending with a `<!-- mel:questions -->` trailer split across deltas), `change-answer` (the card's answer as a change: `{"edits": [{"file", "old", "new"}]}` in `result`, like every change run), `experience`, `architecture`, `tasks`, `analyze-issues` (`{"issues": []}`: the missing task is Mel's own finding), `change-task` (the fix for it), `change-unplaced` (two edits; the ARCHITECTURE.md one has no place), then `architecture` again as the rewrite, and `change-remove` (`{"edits": []}`: nothing else was built on the removed story). `requirements-partial` (no `result`, replayed in `hang` mode to test Stop) and `requirements-full` serve the stop and lost-session tests.

Drafts carry `<!-- mel:step N -->` markers, which drafts wrote before 0.5; Mel still strips them. A `hang` file stays under 10 lines because `hang` replays with `tail -f` (last 10 lines only), and its `Read` comes last, so once the session shows it, every delta has arrived.
