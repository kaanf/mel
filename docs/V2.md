# Mel v2

The v2 design is the target (OPEN-QUESTIONS #20). Where this file differs from PRODUCT, REQUIREMENTS, UI, DESIGN, SPEC-FORMAT or AGENT-INTEGRATION, **this file wins**. Those docs are updated as each wave lands.

- Design source: [`docs/design/v2/`](design/v2/). Read `FLOW.md` first; every `.dc.html` starts with a `MEL SCREEN` comment (id, purpose, entries, exits). Live canvas: https://claude.ai/artifact/EoySYJYRhntvx3G6u19EFd
- Ships as **v0.3**, once, when all of it works. No in-between release with half the flow.

## 1. Look

- **Pixel-exact.** Colors, spacing, padding, radii, font sizes, weights and line heights are taken from the `.dc.html` inline styles. They live as named tokens in one file (`Mel/Views/Theme.swift`); views use tokens, never literals.
- **Light mode only.** The app forces the Aqua appearance; no dark variants.
- **Real macOS window.** Traffic lights, title bar, window corners and shadow are the system's. Everything inside the window matches the design. The mock's grey page background (`#dfe0e5`) and window frame are not drawn.
- Fonts: SF Pro (system) at the drawn sizes; SF Mono where the mock uses `SF Mono`. Icons: SF Symbols that match the drawn glyph.
- Logo: honeycomb icon from `Mel-Logo.dc.html` (small mark at 16 px).

## 3. Projects and folders

Everything belongs to a project (a folder, usually a git repo).

```
<project>/
├── AGENTS.md                         optional, written from B7 (Mel's block between markers only)
├── .mel/project/                     project context, written once (A3), committed
│   ├── product.md  tech.md  structure.md  principles.md
└── specs/
    └── <spec-slug>/                  one folder per spec
        ├── REQUIREMENTS.md …         the size's files (§4)
        ├── DECISIONS.md              every answer and change with its reason
        ├── prompts/task-01.md …      per-task prompts, written at handoff
        └── .mel/                     app state, never committed
            ├── state.json
            └── approved/<FILE>.md    snapshot at approval, for C1's diff and Undo
```

- The library is a list of **project** bookmarks. Specs are found by scanning `specs/*/.mel/state.json`.
- A2 lists git repos one level under `~/Developer` (if it exists).
- **Start from an Idea** (no project): Mel creates `<chosen parent>/<slug>/` as a new project; the spec goes to `specs/<slug>/`. Only Product size works without a project (A4x).
- A3 runs once per project. "New project, no code yet" mode is picked automatically for an empty folder; the toggle stays as drawn.

## 4. Sizes and files

| Size | Intake | Files, in order | Then |
|---|---|---|---|
| Quick fix | 1–2 questions | SPEC.md | Spec ready |
| Feature | about 3 | REQUIREMENTS, ARCHITECTURE, TASKS | Analyze → Spec ready |
| Product | about 5 | PRODUCT, REQUIREMENTS, EXPERIENCE, ARCHITECTURE, TASKS | Analyze → Spec ready |

A file unlocks only after the one before it is approved. DESIGN.md is gone: its UX part becomes EXPERIENCE.md, the rest ARCHITECTURE.md.

## 5. The flow, mechanically

- **Project context (A3).** One read-only agent run over the repo returns the four files as JSON; Mel writes them. "Add Rule" appends to `principles.md`; "Edit Files" opens `.mel/project/` in Finder. Every later prompt includes the four files.
- **Builds on (B1, Feature).** Chips come from `structure.md`'s `## Modules` list (`- Name — path`), plus "Something new".
- **Attachments (B1).** Add Files / drop / Paste Log copy into `specs/<slug>/.mel/attachments/`; prompts pass their paths (Claude Code reads them with its Read tool).
- **Intake (B2).** One agent run returns **all** round-1 questions and the coverage list as JSON at once (no run per question). "Draft Now" skips the rest; skipped questions become assumptions.
- **Round 2 and open questions.** A draft may end with up to 3 gap questions in a trailing `<!-- mel:questions … -->` comment, which Mel strips. They show in B4's "Before you approve". Answering a round-2 or open question starts a **revise** run of that file (B3, then B4 again).
- **Drafting (B3).** The step checklist per file kind is fixed in the prompt; the agent emits `<!-- mel:step N -->` markers that Mel strips and uses to move the checklist.
- **Review (B4, B5).** Open questions (`[!OPEN QUESTION]`) and assumptions may stay; **Approve works anyway** (OQ #18). Confirm/Change on assumptions stays. Approve saves the snapshot and records confirmed assumptions in DECISIONS.md.
- **Analyze (B6).** One read-only run over all approved files returns JSON: stats, issues (kind, where, text, two actions with a fix instruction each) and the coverage matrix. "Fix n Issues" / an issue's action starts revise runs of the affected files in file order; each is reviewed in B4; Analyze reruns after. "Hand Off Anyway" goes to B7.
- **Refine (C1).** Editing an approved file marks it `edited` and every later file `stale`. One run returns what each stale file is affected by (C1's "What this affects"). "Why did this change?" is saved as a decision that replaces the older one. Undo restores the snapshot. Refine runs revise for each stale file; Keep Them as They Are clears `stale`.
- **Handoff (B7).** Mel writes `prompts/task-NN.md` from TASKS.md (task, the criteria it covers in full, what it reads, verify command). "Write AGENTS.md" adds or updates only Mel's marked block. Commit commits `specs/<slug>/` (minus `.mel/`) and `.mel/project/`.
- **Stopped (C2).** Resume Later (notification when the limit resets) or Finish it myself.

Invariants stay: Mel is the only writer; Claude Code runs without write or shell tools; never overwrite a user's edit; atomic writes.

## 6. File formats (SPEC-FORMAT is rewritten from this in Wave 6)

- REQUIREMENTS: stories `## 1. Title` with a `P1 · MVP` / `P2` tag line, `Source:` line, EARS criteria `- 1.1 WHEN … THE APP SHALL …`, an `MVP line` marker, `## Quality requirements` (`- Q1 …`), `## Edge cases`.
- EXPERIENCE: `## Flow N · Name` with `Covers:`; `## Screens and states` table (Screen | States | Criteria; a missing state is prefixed `!`); `## Visual direction`.
- ARCHITECTURE: modules, data, API, decisions.
- TASKS: `- [ ] N. Title` with `Priority: P1`, `Covers:`, `Reads:`, `Verify:` and an optional `Parallel with:`.
- SPEC.md (Quick fix): what breaks, expected behavior, how to verify, code it touches, out of scope.
- DECISIONS.md: `## D-07 · Title`, reason, source/date, `Replaces: D-03`, `Affects: 1.3`.
- Callouts: `[!ASSUMPTION]` and `[!OPEN QUESTION]`.

## 7. Sidebar statuses

`locked` (shown "Queued" during intake, "Locked" after), `writing` ("Drafting"), `review`, `approved`, `stopped`, `edited`, `stale` ("Out of date"). Analyze row: Queued / Locked / n issues / Passed / Rerun.
